01

Spacing & grouping

Space is structure. Repetition makes a system feel intentional; a larger jump tells people a relationship has changed.

S01Evergreen

Use a small spacing scale

Choose a handful of distances and reuse them. The consistency is more valuable than finding a perfect number each time.

CSS → Fluttergap: 8px → const SizedBox(height: 8) padding: 16px → EdgeInsets.all(16)
S02Evergreen

Make separation visibly larger

Use the next step or two inside a related group; use a bigger jump between sections, tasks, or decisions. A divider supports that distinction—it does not replace it.

FlutterColumn(children: [ relatedRows, const SizedBox(height: 24), nextSection, ])
S03Apple layout

Give important things air

Do not pack a control against its explanation, a title against the next section, or the shell against the content. Empty space is a grouping and reading tool.

FlutterPadding( padding: const EdgeInsets.fromLTRB(24, 20, 24, 24), child: content, )
S04Evergreen

Put related things closer

A label belongs near the value it describes. A title belongs closer to its subtitle than to the next card. Proximity should explain the structure without relying on boxes.

FlutterColumn(crossAxisAlignment: CrossAxisAlignment.start, children: [title, const SizedBox(height: 4), description])
02

Hierarchy & layout

Make the screen’s main job obvious before anyone reads the details.

H01Frontend design

Give each screen one primary job

Lead with the thing people need to understand or do. Supporting information should reinforce it, not compete for equal attention.

FlutterScaffold( appBar: appBar, body: primaryTask, )
H02Evergreen

Separate title from configuration

The title says what this is; the controls say what can change. Make the title a stable header, then group the editable properties below it.

FlutterColumn(children: [ SheetHeader(title: title, subtitle: summary), const Divider(), propertyControls, ])
H03Apple layout

Align to a shared edge

Repeated left edges and baselines reduce visual noise. Break alignment only when it communicates a genuinely different level or behavior.

FlutterColumn( crossAxisAlignment: CrossAxisAlignment.start, children: children, )
H04Evergreen

Do not box every group

Use cards when they establish a meaningful container, selection, or independent action. Prefer spacing, headings, and a quiet divider for ordinary grouping.

Flutter// Prefer this for a simple group: Padding(padding: const EdgeInsets.symmetric(vertical: 16), child: rows)
03

Type & language

Text has jobs: orient, explain, label, and guide an action. Do not make a reader decode your structure.

T01Frontend design

Use type roles, not arbitrary sizes

Establish a compact title, body, label, and data style. Change size, weight, or colour only when it expresses a real change in role.

Flutterfinal type = Theme.of(context).textTheme; Text(title, style: type.titleMedium) Text(detail, style: type.bodyMedium)
T02Apple accessibility

Descriptions must be readable

Supporting copy should clarify a decision, not become tiny grey decoration. Use a body size and contrast that still work at a glance and under text scaling.

FlutterText( description, style: Theme.of(context).textTheme.bodyMedium, )
T03Frontend design

Name the thing people control

Use familiar, direct language: “Text scale,” not “Typographic scalar”; “Show labels,” not “Semantic mode.” A label names, an example demonstrates, and a button acts.

FlutterText('Reduce motion') Text('Limit non-essential animation') Button(child: Text('Reset preview'))
T04Evergreen

Design for scanning first

Put the important words early, use short labels, and make key values easy to compare. People scan a settings panel before they read it.

FlutterRow(children: [ Expanded(child: Text('Text direction')), DirectionControl(), ])
04

Colour & states

Colour should carry stable meaning, and the interface should remain usable when it does not.

C01Evergreen

Give signal colours one meaning

Use the same colour for the same kind of information. For example, if pink marks selection and focus, do not also use it as a spare decorative accent.

Flutterfinal color = selected ? tokens.focusPink : tokens.neutralForeground;
C02WCAG

Never communicate state by colour alone

Pair colour with a label, icon, shape, position, or text. “Off” beside a switch still explains the state in monochrome.

FlutterRow(children: [ Text(enabled ? 'On' : 'Off'), const SizedBox(width: 12), Switch(...), ])
C03WCAG

Protect contrast in every state

Check regular text, disabled-looking content, selected surfaces, focus outlines, and errors—not just the default screen. Muted does not mean illegible.

Flutter// Put contrast-tested roles in theme tokens; // do not tune greys locally in each panel.
C04Evergreen

Use quiet surfaces for structure

Let surface, border, and elevation establish containment. Reserve saturated colour for an intentional signal, not every card, chip, and icon.

FlutterContainer( decoration: BoxDecoration( color: tokens.surface, border: Border.all(color: tokens.divider), ), )
05

Controls & accessibility

A control is usable only when it can be reached, understood, operated, and given feedback.

A01Apple / WCAG

Make hit targets generous

Use 44×44 logical pixels as a practical target for primary touch controls. WCAG 2.2 AA defines a 24×24 CSS-pixel minimum with exceptions; bigger is usually kinder.

FlutterSizedBox( width: 44, height: 44, child: IconButton(icon: icon, onPressed: onPressed), )
A02Apple / WCAG

Keep keyboard focus visible

Keyboard users need to see where they are, even within dense desktop tooling. The focus treatment must not be hidden behind adjacent content or convey selection ambiguously.

FlutterFocusableActionDetector( onShowFocusHighlight: setFocused, child: control, )
A03Apple accessibility

Label the control, not its mechanics

Say what changes and what the current state is. Avoid making people infer an icon’s meaning, a switch’s target, or a knob’s unit.

FlutterSemantics( label: 'Bold text', value: enabled ? 'On' : 'Off', child: Switch(value: enabled, onChanged: setEnabled), )
A04Evergreen

Make the result of an action clear

A change should look changed; an error should say what is wrong and how to recover. Do not rely on a silent tiny animation as confirmation.

FlutterScaffoldMessenger.of(context).showSnackBar( const SnackBar(content: Text('Preview reset')), );
06

Responsive Flutter translation

Adapt the arrangement to the available space; do not give the user a shrunken version of a layout that no longer fits.

F01Flutter practice

Respond to constraints, not device names

Choose a layout because the content has room, not because the screen is called “tablet.” Test the narrow and wide states with real text.

CSS → Flutter@media (min-width: 720px) → LayoutBuilder(builder: (_, box) { final wide = box.maxWidth >= 720; return wide ? Row(...) : Column(...); })
F02Flutter practice

Let content take the flexible space

Give labels room to wrap before squeezing controls. Avoid fixed widths for a text column when the component can naturally flex.

CSS → Flutterflex: 1 → Expanded(child: label) gap: 12px → Row(children: [label, SizedBox(width: 12), control])
F03Apple layout

Constrain long reading lines

A fluid canvas still needs readable text measure. Let content grow, but place explanatory text in a sensible maximum width.

CSS → Fluttermax-width: 65ch → const ConstrainedBox( constraints: BoxConstraints(maxWidth: 680), child: Text(description), )
F04Flutter practice

Preserve intended constraints in demos

A demo or gallery should show a widget under the constraints it is designed for. Do not make a component appear compact by quietly passing unrealistic constraints.

Flutter// Demonstrate the actual intended size. SizedBox(width: logicalWidth, child: component)
07

Shared Flutter practice

These are reusable habits for a Flutter design skill. They should stay practical and composable, not become a heavyweight process.

P01Flutter practice

Review the real widget in its real theme

Design feedback should apply to the actual Flutter widget with its app theme, typography, and layout conditions. A surrogate gallery can hide the exact thing being judged.

FlutterMaterialApp( theme: appTheme, home: RealWidget(), )
P02Flutter practice

Keep one source for shared design decisions

Centralise a shared colour role, type role, or spacing value instead of reproducing a near-match in each widget. One change should update every intended use.

Flutterfinal theme = ThemeData( colorScheme: colorScheme, textTheme: textTheme, );
P03Evergreen

Expose complexity progressively

Show the default action and the information needed to use it. Put unusual options nearby but out of the main path until they are relevant.

FlutterExpansionTile( title: const Text('Advanced options'), children: advancedControls, )
P04Prototype skill

Prototype before promoting a shared API

Compare a few focused widget directions before fixing an interface into a reusable component. Keep the winning intent; do not harden every visual experiment into an API.

FlutterWidget buildPrototype(BuildContext context) { return Column(children: [directionA, directionB]); }
