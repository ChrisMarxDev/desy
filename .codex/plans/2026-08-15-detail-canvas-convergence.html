Detail canvas convergence

Plan to retire the duplicate hand-built detail canvas in favour of the shared collection-canvas engine, while adopting desy.component.knob-sheet as the definitive detail-control surface.

Draft2026-08-15No backend or persistenceRegistry remains source of truth

Goal and scope

Ship now

  • Draw opted-in drag-box frames outside the preview clip.
  • Use the real segmented knob-sheet layout throughout Details.
  • Remove the all-components /canvas destination and its duplicate screen.

Plan next

  • Generalise the shared canvas for a host-managed preview environment, per-item capture boundary, and device geometry.
  • Move Detail variants onto it only after parity tests pass.

Touched files and classes

Logic and data flow

DesyRegistry entry
  → DesyDetailScreen builds typed variants + preview environment
  → phase-one _DetailInstanceGallery (unchanged scene policy)
  → DesyDragBox outside frame + real preview clip
  → persistent Detail knob sheet
      → session.setKnob / preview accessibility / device / motion / export

phase two
  → DesyDetailCanvasItem adapter
  → DesyCollectionCanvas scene engine
  → host wrapper: accessibility + inspection + device + capture boundary

All values remain in the existing workbench session or local detail controller. No callbacks, widgets, or user placements are persisted.

State model and UI transitions

Existing owners retained

  • DesyWorkbenchSession: knob values, accessibility settings, selected device and stage.
  • _DetailInstanceGalleryState: temporary geometry, active variant, camera, capture keys.
  • _DetailImageExportController: export busy/status lifecycle.
  • DesyMotionPlaybackController: motion lifecycle.

Transitions

  • Selection keeps the current controls panel; no drawer swap in Details.
  • Device change re-derives fixed device frame and fit transform.
  • Resizing retains immediate geometry updates; external frame never intercepts pointers.
  • Phase-two engine migration keeps the same visible initial layout and keyboard semantics.

Backend and database changes

None. The consumer registry stays local, immutable, and code-owned. Canvas placement remains ephemeral after opening a Detail screen.

Tests and verification

Risks and open decisions

  • Do not migrate Detail to the generic canvas yet. It would lose device bezel/aspect-lock, preview environment, capture/export, and persistent resize-panel behavior today.
  • Recommended default: use the generic canvas only after it gains host-owned wrappers and item policies. Then Details and Prototypes share engine mechanics, but not necessarily the same inspector presentation.
  • The outside border must be opt-in to avoid changing Sketch and existing Detail geometry unexpectedly.
  • Removing /canvas may break saved/deep links; redirect it to Atlas for one release if compatibility is required. Recommended: redirect rather than leave a dead route.
