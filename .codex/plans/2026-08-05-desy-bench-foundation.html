Logic and data flow

Status
Consumer source
  └─ DesyRegistry(themes, root entries, folders)
       └─ DesyRegistryScope (single app-wide access point)
            ├─ Folder tree → nested Forui navigation
            ├─ Atlas → entries at selected folder path (no parallel Atom inventory)
            ├─ Inspector → selected entry metadata + real preview
            ├─ Preview canvas → logical preview size → scale transform → fit surface
            └─ Future ScreenRegistry → code screens + saved manifests

No adapter owns a second registry. Folders retain paths; flattening is a derived
query only for search and global counts.

UI states and transitions

Status
  • Initial: select the first non-empty folder/entry; show an intentional empty Atlas if the tree has no entries.
  • Folder switch: preserve search when appropriate; crossfade Atlas content and animate sidebar selection.
  • Entry open: animate grid-to-inspector transition; keep preview dimensions and theme selection stable.
  • Scaled preview: render the consumer widget in a declared logical viewport, calculate the fit scale from available canvas bounds, and animate scale changes with a short ease-out. Pointer interaction follows the transform; a visible scale readout makes the canvas honest.
  • Theme switch: crossfade only the consumer preview wrapper; Desy chrome stays in its own Forui theme.
  • Search: query the derived tree index; show a useful “No declared entries match” state, not a blank grid.
  • Preview errors: catch preview-builder exceptions in a bounded error card with entry ID and retry; one faulty consumer widget must not crash navigation.

Backend and database changes

Status

None planned. The registry is repository-local Dart source. The later manifest store will need a separate persistence decision (file format and location) before any database, backend, migration, RLS, or deploy work is introduced.

Risks and seams to watch

Status
  • The current prototype port contains duplicate legacy models. Treat the adapter as a migration bridge, not a public API.
  • Atoms is a structural folder only. Color/treatment entries must live at Atoms/Colors and must not also appear as generic atoms.
  • Folder nesting must not turn into a required taxonomy; an entry can remain at root.
  • Forui governs Desy chrome only. Accidentally applying it inside a consumer preview violates the real-context principle.
  • Folder traversal needs duplicate-ID and cycle-safe validation before user-composed manifests use it.
  • Saved-screen composition is intentionally deferred; no implicit persistence or generated Dart code belongs in this foundation slice.
