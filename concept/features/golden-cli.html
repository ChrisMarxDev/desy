Golden evidence attached to the design journey.

A local CLI renders deterministic registry-selected matrices, while the Registry Spine shows the focused artifact’s result as a concise receipt in the current activity stream and promotion review.

Reason and user value

Golden tests are valuable but expensive to author and keep organized. Desy already knows what can render and how it should be addressed. The CLI converts that inventory into intentional, reviewable coverage without creating a separate gallery.

Scope

  • desy golden plan: preview the capture matrix.
  • desy golden capture: create missing baselines.
  • desy golden verify: compare without mutation.
  • desy golden update --accept: explicit baseline acceptance.
  • desy golden diff: emit images plus registry state and source context.
  • Selection by stable IDs, paths, themes, scenarios, or tags derived from typed lanes.

Non-goals

  • No silent golden updates.
  • No hosted comparison service.
  • No promise of pixel stability across arbitrary Flutter SDKs and operating systems.
  • No automatic capture of every combinatorial knob value.

Implementation sketch

  1. Consumer supplies a tiny Flutter test entrypoint that imports its registry.
  2. The CLI writes only ephemeral runner configuration under .dart_tool and invokes flutter test.
  3. A versioned capture recipe records registry ID, values, theme, viewport, pixel ratio, fonts, locale, and settle policy.
  4. Store PNGs and recipe metadata in consumer source control.
  5. Emit human output plus stable JSON for agent tooling.

The exact launcher is an open technical spike: Flutter rendering must remain inside the test binding even if a thin Dart command orchestrates it.

Open questions

  • Should the public command be a global executable or dart run?
  • How are fonts and platform rendering pinned?
  • What constitutes “affected” without a usage graph?
  • Should animation capture use a fixed clock or named frame checkpoints?

Do or don’t?

Do a selected-matrix MVP. Impact 5/5, complexity 3/5, risk 2/5. Defer affected-only selection and cross-platform normalization until deterministic local captures are proven.

Decision: CLI orchestrates Flutter test infrastructure; the registry remains the only capture inventory.
