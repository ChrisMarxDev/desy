Rank 2 · Agent workflow

Agent briefs grounded in the real design system.

Replace the inert AI Prompts destination with a local context composer that packages exact registry facts, selected preview state, source paths, and verification commands for any coding agent.

Reason and user value

Agents frequently invent components, restyle existing widgets, or miss legal instances because the design system is scattered across source. Desy can hand over the declared component interface and the exact visual state the developer is looking at.

Win: less prompt assembly, fewer fake widgets, and a reproducible target for the agent.

Scope

  • Choose an entry, instance, scenario, theme, viewport, and current knob values.
  • Generate Markdown and machine-readable JSON from the registry.
  • Include source paths, contracts, legal slots, related primitives, screenshot path, and focused commands.
  • Copy to clipboard or save inside the repository.
  • Offer task presets: implement, fix, review, make responsive, add instance.

Non-goals

  • No embedded general-purpose chat client.
  • No vendor-specific agent API in core.
  • No hidden workspace scanning beyond explicitly derived context.
  • No production code generation.

Implementation sketch

  1. Extract a shared DesyAgentContextBuilder from catalogue export and detail state.
  2. Define a versioned brief schema and deterministic Markdown renderer.
  3. Mount a Forui screen at the existing AI Prompts route.
  4. Add optional screenshot capture through the screenshot extension boundary.
  5. Expose the same builder to the future CLI.

Smallest useful flow

Select component state→Choose task intent→Preview brief→Copy/save→Agent runs stated checks

Open questions

  • Should related primitives be derived from static usage analysis or omitted until trustworthy?
  • Where should saved briefs live by default?
  • Should screenshots be required or opportunistic?
  • How much source content belongs in a brief versus file paths?

Do or don’t?

Do. Impact 5/5, complexity 2/5, risk 1/5. The UI route and registry export already exist, and this validates the agent product thesis without a CLI, backend, or new declaration burden.

Decision: build first; make every output reproducible and registry-derived.
