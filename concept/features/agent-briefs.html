Rank 3 · Agent context

The right rail already knows what you are looking at.

Continuously resolve the active registry artifact, selected widget, source location, theme, viewport, annotations, and verification commands into one structured context object for the current resumable agent session.

Reason and user value

Agents frequently invent components, restyle existing widgets, or miss legal instances because the design system is scattered across source. Desy can hand over the declared component interface and the exact visual state the developer is looking at.

Win: less prompt assembly, fewer fake widgets, and a reproducible target for the agent.

Scope

  • Track the active entry, instance, scenario, theme, viewport, knob values, selected candidate, and widget target.
  • Include source paths, contracts, legal slots, related primitives, committed annotations, and focused commands.
  • Render a concise human summary in the right rail and pass the full typed payload to the runtime.
  • Support deterministic Markdown and JSON for clipboard, logs, and future CLI use.
  • Update context reactively as focus changes without starting a new session.

Non-goals

  • No separate AI Prompts screen.
  • No vendor-specific context model in the registry.
  • No hidden workspace scan presented as registry truth.
  • No copied catalogue or production code generation.

Implementation sketch

  1. Define one immutable DesyWorkspaceFocus and one DesyAgentContextBuilder.
  2. Resolve stable IDs through the app-wide registry and attach source-aware annotation targets.
  3. Let the right rail observe focus and current session state.
  4. Send the typed context with every agent turn while showing only a concise summary.
  5. Expose deterministic renderers to future CLI commands without changing the payload.

Smallest useful flow

Focus artifact→Select widget→Annotate→Send current context→Hot reload

Open questions

  • Should related primitives be derived from static usage analysis or omitted until trustworthy?
  • Where should saved briefs live by default?
  • Should screenshots be required or opportunistic?
  • How much source content belongs in a brief versus file paths?

Do or don’t?

Do as shared workspace infrastructure, not another destination. Impact 5/5, complexity 2/5, risk 1/5. Most source facts already exist; the value is keeping them synchronized with visible focus and the current agent session.

Decision: context follows focus inside the Registry Spine; it never becomes a second catalogue or separate prompt product.
