Feature index

See the real system. Workshop what it becomes.

Desy’s core loop starts in the registry-driven Atlas, carries real components and theme context into code-backed workshops, and returns repository changes through Flutter hot reload. Agent briefs, verification, and optional adapters strengthen that loop without becoming separate products.

Registry→Atlas→Workshop→Real Dart + hot reload→Atlas

Architectural decision

Make Atlas + Workshop the primary product path. The consumer registry remains the only design-system inventory; workshop context stores stable IDs and resolves them live. Surface manifests, JSON widgets, A2UI, and SDUI remain optional adapters or labs and do not appear in the core navigation.

Recommended sequence

  1. Join Atlas and the hot-reload Workshop around one registry context.
  2. Use Agent Briefs and semantic intent inside that loop.
  3. Add render-object selection and state-rich annotations.
  4. Add deterministic golden verification for accepted directions.
  5. Move JSON widgets and speculative editors out of primary navigation.
  6. Only then evaluate conformance, manifests, A2UI, SDUI, or hosted compilation against demonstrated needs.

Shared enabling work

  • Typed workshop seed containing registry IDs and preview state.
  • Optional entry actions contributed by workspace extensions.
  • Ordinary Dart candidate-file boundary.
  • Hot-reload runtime separated from the Workshop UI.
  • Stable registry export and deterministic rendering for later agent and verification work.
