From visual observation to verified agent fix.

Extend agent annotations from a comment callback into a reproducible local work item containing the exact registry state, screenshot evidence, and verification receipt.

Reason and user value

“The padding looks wrong here” is weak agent input. “Component X, instance Y, theme Z, width 390, these knob values, this screenshot, expected golden plan” is actionable and can be reopened after the patch.

Scope

  • Snapshot selected entry, instance, scenario, values, theme, viewport, locale, and text scale.
  • Attach screenshot and source paths when available.
  • Persist through the existing consumer-owned callback.
  • Generate an Agent Brief from an annotation.
  • Accept a verification receipt: commands run, resulting capture, status, and comment.
  • Reopen the exact state in Desy.

Non-goals

  • No issue tracker or account system in core.
  • No autonomous patch execution from the workbench.
  • No mutation of registry declarations.
  • No universal “resolved” state without consumer-owned persistence.

Implementation sketch

  1. Add a versioned DesyPreviewState value object.
  2. Extend annotation payloads compatibly with optional evidence.
  3. Add “Create agent brief” and “Reopen state” actions.
  4. Define a verification receipt independent of any agent vendor.
  5. Dogfood using the existing local Markdown sink.

Loop

Observe→Snapshot→Agent brief→Patch→Golden verify→Receipt

Open questions

  • Should screenshot evidence be bytes, a repository path, or sink-owned?
  • How are annotations migrated when registry IDs change?
  • Can the workbench deep-link directly to a serialized preview state?
  • What evidence is required before a sink may mark an item verified?

Do or don’t?

Do incrementally. Impact 4/5, complexity 3/5, risk 2/5. State snapshot and brief generation are the valuable core; task dispatch and status storage remain consumer concerns.

Decision: enrich the existing extension boundary; do not add a second task system.
