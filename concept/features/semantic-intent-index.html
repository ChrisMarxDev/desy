Rank 2 · Semantic registry search

Search the Registry Spine by the job to be done.

Names expose inventory. Developers and agents need intent, constraints, examples, and explicit alternatives to choose an existing artifact before writing another one.

Impact 5/5Complexity 3/5Risk 2/5

Reason and user value

An agent searching for “submit action” should find the approved primary button, learn when not to use it, discover its loading/error scenarios, and avoid inventing a visually similar widget.

Scope

  • Sidebar search and keyboard discovery over the existing derived registry tree; no second index of components.
  • Optional intent tags, use cases, anti-use-cases, semantic roles, and search aliases on rich registry objects.
  • Relations such as alternative-to, composed-with, supersedes, and requires.
  • CLI query by task intent with explainable ranked results.
  • Examples derived from registered scenarios and surfaces.
  • Locale-independent stable vocabulary with consumer display labels.

Non-goals

  • No vector database required in core.
  • No opaque model-generated ranking as the only answer.
  • No duplicate catalogue or prose file that can drift from the registry.
  • No requirement that every component declares metadata.

Implementation sketch

  1. Start with deterministic name, path, and typed-lane filtering in the Registry Spine sidebar plus keyboard focus.
  2. Add small composable intent and relation value objects only where lexical search cannot answer “when and why.”
  3. Return match reasons and legal instances through CLI JSON.
  4. Let an optional agent layer re-rank, while preserving deterministic evidence.
  5. Dogfood with ten common UI intents and measure selection accuracy.

Open questions

  • Which vocabulary is universal enough to ship as typed values?
  • Should intent attach to components, instances, contracts, or all three?
  • How are deprecated components represented and migrated?
  • Can scenario names provide enough initial intent without new metadata?

Do or don’t?

Do, but keep metadata optional. The registry already answers “what”; this supplies “when and why,” which is the missing ingredient for reliable agent selection.

Offline concept artifact. No remote assets or runtime dependencies.
