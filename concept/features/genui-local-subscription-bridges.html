Local subscription experiment

Use a person’s existing local agent subscription without copying a key into Orbit.

Orbit can hand one constrained GenUI turn to either signed-in Codex or signed-in Claude Code. If the CLI is missing, a minimal onboarding screen opens Terminal with the visible official installer and interactive sign-in flow.

Reason and value

A desktop GenUI experiment should be easy to try with the subscriptions people already use, while keeping credentials inside the provider-owned CLI and browser login flow.

Decision

Ship the narrow macOS experiment: one Codex app-server bridge, one Claude Code print-mode bridge, one separate button-only setup component for each provider, and an app-owned controller that selects and owns the active provider backend.

Scope

Orbit button→Terminal installer + browser sign-in→Provider CLI credential store→Local GenUI bridge
  • Probe codex or claude through the user’s login shell.
  • Only when absent, open the provider’s official macOS installer in Terminal.
  • Run codex login or start claude so its normal sign-in flow remains visible and interactive.
  • Use Codex app-server or Claude Code structured output to return a constrained GenUI surface.
  • Select the provider inside Orbit; provider identity is reactive app state, not a launch-time environment variable.

Non-goals

  • No API-key text field, key storage, or account management in Flutter.
  • No hidden package-manager install or silent browser authentication.
  • No shared provider abstraction that obscures each CLI’s real protocol.
  • No mobile, web, Windows, or Linux guarantee in this slice.

Open questions

  • Should Claude turns stream A2UI partials after the complete-tree bridge proves useful?
  • Should the setup screen re-check availability after the user returns from Terminal?
  • What per-turn tool and spend policy should a production local bridge expose?

Implementation sketch

  1. Keep platform process and Terminal launching behind a conditional Dart import.
  2. Give Codex and Claude sibling bridge folders with their own commands and protocol adapters.
  3. Render two separate, keyboard-accessible onboarding components through Orbit’s real controls.
  4. Use the state-beacon-backed app controller to select, route to, and dispose the active provider backend through the existing provider-neutral GenUI contract.

Do it, narrowly

Impact 4/5 · Complexity 3/5. The capability removes the largest trial barrier for a local desktop experiment and preserves provider ownership of authentication. It is worth building only as an explicit, user-visible macOS flow; silently changing a machine or storing credentials in Flutter would reverse the safety and trust benefit.
